## 1. 项目概览

### 1.1 这是什么

AutoBangumi 是一套自动化追番工具：订阅番剧 RSS 源后，自动解析标题、下载种子到下载器、重命名整理成媒体库规范命名。本 Fork 基于原版 3.3，面向自用场景做了增强（Jellyfin 集成、剧集总览、订阅检查计划、连通性测试等），前后端打包在同一个容器里，单容器即可部署。

- 后端：FastAPI（Python 3.13），同时托管 WebUI 静态文件
- 前端：Vue 3 + Naive UI + UnoCSS
- 数据：SQLite（`/app/data/data.db`），启动时自动执行数据库迁移

### 1.2 核心工作流

```
RSS 订阅源（Mikan 等）
      │  按检查计划到期抓取
      ▼
标题解析（集数/季/字幕组/分辨率）──◆ Jellyfin 在库比对【Fork 新增】
      │                              已在库的集可跳过下载
      ▼
下载器（qBittorrent / aria2）
      │  应用侧先取回 .torrent 文件再投递
      ▼
（可选）重命名整理 ──► 媒体库（Jellyfin 等）
      ▲
剧集总览【Fork 新增】：查看/手动修正每集状态、手动下载
```

### 1.3 术语表

| 术语 | 含义 |
|---|---|
| 订阅（Bangumi） | 一部番的追踪记录，含官方标题、季、偏移、检查计划等规则 |
| RSS 源 | 订阅对应的报文地址，按计划抓取新种子 |
| 报文 | RSS 返回的种子列表，每条含标题与 .torrent 下载地址 |
| 检查计划 | 订阅的抓取节奏：固定间隔 / 每周定时 / 未定时（跟随全局）【Fork 新增双模式】 |
| 剧集总览 | 按集聚合的订阅详情视图【Fork 新增】 |
| 在库 | 某集已存在于 Jellyfin 媒体库（按剧集名+季+集比对）【Fork 新增】 |
| 偏移 | RSS 标题集数与实际集数的差值修正 |
| 放送星期 | 该番每周几播出，用于番剧日历排期 |

## 2. 部署

### 2.1 Docker Compose 部署（推荐）

```yaml
services:
  AutoBangumi:
    image: shiamiea/auto-bangumi:latest
    container_name: AutoBangumi
    environment:
      - TZ=Asia/Shanghai
      - PUID=1000
      - PGID=1000
      # - AB_WEBUI_PORT=7892   # 可选：改容器内 WebUI 端口
    volumes:
      - ./config:/app/config    # 配置文件
      - ./data:/app/data        # 数据库、日志、海报
    ports:
      - "7892:7892"
    restart: unless-stopped
```

启动：`docker compose up -d`

### 2.2 docker run 部署

```bash
docker run -d \
  --name AutoBangumi \
  -p 7892:7892 \
  -v $(pwd)/config:/app/config \
  -v $(pwd)/data:/app/data \
  -e TZ=Asia/Shanghai \
  -e PUID=1000 -e PGID=1000 \
  --restart unless-stopped \
  shiamiea/auto-bangumi:latest
```

### 2.3 环境变量参考

| 变量 | 默认 | 说明 |
|---|---|---|
| `TZ` | `Asia/Shanghai` | 时区 |
| `PUID` / `PGID` | `1000` / `1000` | 容器内进程 UID/GID，与挂载目录属主匹配 |
| `AB_WEBUI_PORT` | `7892` | WebUI 监听端口。**每次启动都生效**（优先于配置文件），健康检查自动跟随【Fork 增强】 |
| `AB_INTERVAL_TIME` | - | 首次引导时写入「未定时订阅的检查间隔」 |
| `AB_DOWNLOADER_HOST/USERNAME/PASSWORD` | - | 首次引导时写入下载器连接信息 |
| `AB_DOWNLOAD_PATH` | - | 首次引导时写入下载地址 |
| `AB_RSS_COLLECTOR` / `AB_RENAME` 等 | - | 其余首启引导项，仅配置卷为空时生效 |

> **注意**：`AB_WEBUI_PORT` 之外的 `AB_*` 变量只在**首次生成配置文件时**写入，之后以 `/app/config/config.json` 为准。

### 2.4 卷与端口

| 挂载点 | 内容 | 必须持久化 |
|---|---|---|
| `/app/config` | `config.json`（全部设置）、JWT 密钥、搜索源配置 | 是 |
| `/app/data` | SQLite 数据库、日志（`log.txt`）、海报缓存 | 是 |
| `/app/data/posters` | 番剧海报（API `/posters/...` 提供） | 随 data 卷 |

端口 `7892` 同时提供 WebUI 与 API（含移动端适配界面）。健康检查端点 `/health` 免认证。

### 2.5 首次启动

1. 浏览器打开 `http://<主机IP>:7892`
2. 默认账号 **`admin` / `adminadmin`**（**登录后立即到「用户与访问控制」修改密码**）
3. 设置 → 下载设置：填下载器地址与凭据，点「测试下载器连接」验证【Fork 新增】
4. 主页右上「添加」：粘贴 RSS 链接完成第一个订阅

### 2.6 版本与更新

- `latest`：每次合并到 main 自动构建
- `<commit sha>`：每次构建同时打全量 sha 标签，可精确回滚：
  ```bash
  docker pull shiamiea/auto-bangumi:<sha>
  ```
- 更新方式：`docker compose pull && docker compose up -d`
- 数据库结构随版本自动迁移（当前至 v29），旧数据启动时自动升级，无需手动操作

## 3. 功能详解

### 3.1 主页与订阅卡片

主页按季分组展示全部订阅卡片（海报、标题、集数进度）。【Fork 新增】**鼠标悬停卡片**出现两个操作按钮：

| 按钮 | 作用 |
|---|---|
| ✏️ 编辑规则 | 打开该订阅的规则编辑弹窗（见 [3.3](#33-编辑规则)） |
| 📋 剧集总览 | 打开该订阅的剧集总览（见 [3.4](#34-剧集总览)） |

归档的订阅折叠在「已归档」分组。已完结番剧建议归档而非删除，保留历史记录。

> 界面在小窗口高度下会**整页等比缩放**，不会出现页面级滚动条【Fork 新增】。

### 3.2 添加 RSS 订阅

入口：主页右上「添加」。粘贴 RSS 链接（如 `https://mikanime.tv/RSS/Bangumi?bangumiId=...`）后可展开**高级设置**，内容与编辑规则完全对齐（见 3.3 的字段表）。

【Fork 新增】**「立即下载现有集数」开关**（默认开启，保持原版行为）：

- 开启：订阅时立刻把当前报文里的种子（未在 Jellyfin 库的）投递下载
- 关闭：只登记订阅，按检查计划追新——适合先配置好规则再等更新

#### 「收集」按钮：与「订阅 + 立即下载」的区别

「收集」一次性下载当前报文的**全部**种子，不登记 RSS 订阅、不追新（悬停按钮有行为说明）。它与订阅路径的关键差异在于**是否查询 Jellyfin**：

| 路径 | 是否查 Jellyfin | 行为 |
|---|---|---|
| 订阅时「立即下载现有集数」 | 查（受"订阅时跳过已在库的集"开关控制） | 库里已有的集跳过不下载 |
| 后台追新轮询 | 查（受"追新时跳过已在库的集"开关控制） | 新集先比对，已在库的不下载 |
| **「收集」** | **不查** | 无条件下载报文内全部种子，已在库的集也会重复下载 |

**「收集」对剧集总览标签的影响**：

- **已下载**：成功后报文内全部种子标记为已下载 → 总览里这些集全部显示「已下载」（含本就在库里的集，出现"已在库 + 已下载"并存）
- **已在库**：不受影响——收集不写手动覆盖、不干预比对与基准失效机制（5.2），在库状态仍由 Jellyfin 比对自动得出
- **追新去重**：已标记已下载的集，后续轮询按下载记录去重，不会重复下载
- **缓存**：收集不清总览缓存，标签要等缓存按检查计划过期或手动点「刷新」后更新
- 其他：番剧行落库并标记 `eps_collect`（供番剧补全识别）；未订阅的番收集失败时自动回滚，不留幽灵记录

> **选择建议**：想"补全历史集但库里已有的别重复下" → 用**订阅 + 立即下载**（打开跳过开关）；「收集」适合"把该源全部种子拿下来"的场景。

### 3.3 编辑规则

| 字段 | 说明 |
|---|---|
| RSS 源 | 报文地址，一般不做修改 |
| 过滤 | 正则表达式（`\|` 分隔多个）：**匹配到的标题会被排除**。默认 `720`、`\d+-\d+` 排除 720p 与合集 |
| 季度偏移 | RSS 标题季数 → 实际季数的修正量 |
| 集数偏移 | 集数修正量；旁有「自动检测」按 TMDB 集数推算；悬停感叹号有说明【Fork 新增】 |
| 自动检测放送星期 | 一键获取该番播出日：bgm.tv 日历优先、TMDB 首播日期兜底【Fork 新增】 |
| 内容类型 | 剧集 / 电影（电影走 search/movie 匹配）【Fork 新增】 |
| 检查计划 | 见下 |
| 偏好字幕组 / 偏好分辨率 | 报文存在偏好版本时跳过不匹配的重复发布 |

**检查计划**（双模式，每订阅独立）【Fork 新增】：

| 模式 | 参数 | 适用 |
|---|---|---|
| 固定间隔 | 5 分钟 ~ 24 小时自选 | 常规追更 |
| 每周定时 | 星期（可多选）+ 24 小时制时间（精确到分钟） | 知道固定播出时间的番；如「周日 20:30」，其余时间完全不抓取 |
| 未定时 | 无 | 跟随常规设置的「未定时订阅的检查间隔」 |

### 3.4 剧集总览

入口：卡片悬停 📋 按钮，或 RSS 管理页的入口【Fork 新增】。

**双视图**

- **按集数**：`E01 / E02 / …` 聚合，每集显示 TMDB 放送日期与多版本子列表
- **按原始文件名**：逐条列出报文种子及其解析出的集数（含未匹配番剧的种子）

**三种标签**（点击可手动切换）

| 标签 | 含义 | 来源 |
|---|---|---|
| 已在库（绿）/ 不在库（黄） | 该集是否已存在于 Jellyfin | 自动比对（见 5.1），可手动覆盖（见 5.2） |
| 已下载（蓝） | 种子已投递下载器 | 数据库记录，可手动改 |
| 可下载 | 未下载且可投递 | 默认态 |

**操作**

- 勾选任意条目（含未匹配种子）→ 单个 / 批量**手动下载**
- 勾选后**重置标签**：只清除勾选集的手动覆盖，恢复自动判断（本地即时恢复，不重新加载）
- **刷新**：跳过缓存立即重建（重新拉报文 + Jellyfin 比对）；拉取失败时会**明确报错**且保留旧缓存，不会把失败结果存下来
- 工具栏显示「缓存于 HH:MM」：总览数据缓存在服务端，按该订阅的检查计划到期或手动刷新才重建【Fork 新增】

> **缓存健壮性**【Fork 新增】：报文拉取失败不会写入缓存（失败不被持久化）；`groups` 为空的缓存视为无效、下次读取时自动重建。此前版本存在"空壳缓存永不过期导致总览一直空白"的缺陷，已修复。

### 3.5 番剧日历

按放送星期排布的追番日历。放送星期缺失的番可用编辑规则里的「自动获取」补全；元数据刷新时也会自动补全【Fork 新增】。卡片同样支持悬停操作。

### 3.6 检查调度机制【Fork 新增】

```
后台调度器：每 60 秒一个扫描节拍（与检查间隔解耦）
   ├─ 到期的订阅 → 抓取 RSS 报文 → 解析 → 新集投递下载
   ├─ 未到期的订阅源 → 整轮跳过网络抓取（每周定时的源一周只真正请求一次）
   └─ 聚合分析 / 番剧补全 → 按「未定时订阅的检查间隔」节流执行
```

- 调度精度 ±1 分钟内；已定时的订阅严格按计划执行
- 常规设置的「未定时订阅的检查间隔」**只**作用于未设置检查计划的订阅

## 4. 设置参考

> 修改设置后需「保存并重启」生效；连通性测试按钮**无需保存**即可按表单当前值测试（密钥为掩码或空时自动回退已保存值）。

### 4.1 常规设置

| 项 | 默认 | 说明 |
|---|---|---|
| 未定时订阅的检查间隔（秒） | 900 | 只作用于未设置检查计划的订阅【Fork 语义变更】 |
| 重命名间隔（秒） | 60 | 重命名/整理循环的执行周期 |
| 网页端口 | 7892 | 配置文件中的 WebUI 端口（容器内建议用 `AB_WEBUI_PORT` 环境变量，优先级更高） |
| 调试 | 关 | 调试日志 |

### 4.2 解析设置

| 项 | 说明 |
|---|---|
| 启用 | RSS 解析总开关 |
| 标题解析器 | 经典解析器（稳定）/ 通用解析器（Preview，支持剧集、OVA、剧场版、范围与混合合集）；两种模式不自动互相回退 |
| 排除 | 全局过滤正则（`\|` 分隔），匹配的标题不下载 |
| 语言 | 标题匹配语言（zh/jp/en），影响元数据源的语言偏好 |
| 数据源 / Token / 自定义网址 | 元数据源配置 |

### 4.3 下载设置

| 项 | 说明 |
|---|---|
| 类型 | qBittorrent / aria2（aria2 密码栏填 RPC secret，地址示例 `172.17.0.1:6800`） |
| 地址 | 下载器 WebUI/RPC 地址，**从本容器视角填写**（容器内访问宿主机服务用宿主机 IP 或 `172.17.0.1`，不要写 `localhost`） |
| 用户名 / 密码 | 下载器凭据 |
| 下载地址 | 下载保存路径，**填下载器容器内视角的路径**（见 6.2 排查 Q1） |
| SSL | 下载器是否 HTTPS |
| **测试下载器连接**【Fork 新增】 | 验证地址与认证，附版本信息；区分网络不通 / 凭据错误 / 被封禁（qB 多次失败会封 IP） |

> 本应用把 .torrent 文件**先取回再投递**给下载器，因此 qBittorrent 本身无需为 Mikan 配代理（见 5.3）。

### 4.4 番剧管理设置

| 项 | 说明 |
|---|---|
| 启用 | 下载完成后的整理（重命名）总开关 |
| 重命名方式 | `normal` 原样 / `pn` 番剧名 SxxExx（Jellyfin/Plex 友善，推荐）/ `advance` 附加字幕组等 / `none` 不重命名（交给 MoviePilot 等外部整理工具时选此项） |
| 番剧补全 | 检测到缺集时尝试从聚合源补全历史集 |

## 5. 机制专题

### 5.1 Jellyfin 媒体库比对原理

1. 按**剧集官方标题**在 Jellyfin 搜索 Series（完全匹配 → 去季数尾缀匹配 → 第一个结果兜底）
2. 拉取该剧全部已入库分集，构成 `(季, 集)` 集合
3. 每集判定：精确 `(季, 集)` 命中，或季号不符时按集号兜底
4. **比对按"剧集名 + 季/集"，不看文件名**——库里存的是同剧不同版本资源（如手动整理的 B-Global 版）也能正确识别为已有
5. 匹配失败（找不到剧集/接口异常）一律视为不在库，照常下载

> 比对结果要被采信，前提是"该剧匹配成功"。**空库**（匹配成功但没有该集）也是有效的比对结果；**未匹配到剧集**则不可信，不会触发任何覆盖失效（见 5.2）。

### 5.2 手动标签机制（基准失效）

手动点击「已在库/不在库」标签会写入一条**覆盖记录**，默认**优先于**自动比对。为避免覆盖永久遮蔽真相，本 Fork 采用**基准失效**机制【Fork 新增】：

```
写入覆盖时：同时记录"当时的自动比对结果"（基准）
刷新时：
  ├─ 当前比对结果 == 基准   → 覆盖继续生效（你在纠正持续性误判）
  └─ 当前比对结果 ≠ 基准    → 媒体库状态已变，覆盖使命完成
                              → 自动失效，采用最新比对结果
                              → 界面提示「已自动更新 N 集」
```

- 旧版本写入的覆盖（无基准）**不会**立即失效：首次刷新时以当时比对结果回填基准
- Jellyfin 不可用或剧集未匹配时，比对结果不可信，**不会**失效任何覆盖
- 「重置标签」（勾选后）可随时手动清除覆盖，恢复自动判断
- 手动覆盖的标签带「手」角标

### 5.3 下载链路与代理的关系

```
AutoBangumi ──(走应用代理)──► Mikan RSS / .torrent 文件 / TMDB / bgm
AutoBangumi ──(内网直连)────► 下载器 API、Jellyfin API
下载器 qB ────(自身网络)────► Tracker / Peer   ← 应用管不到这段
```

关键设计：**应用先取回 .torrent 文件内容，再以文件形式投递下载器**。因此：

- Mikan 被墙 → 给应用配代理即可，qB 不需要代理
- qB 只需能连 Tracker / Peer（多数国内 Tracker 可直连）
- 「下载地址」必须填**下载器容器内视角**的路径，否则任务因保存路径不存在立即报错

## 6. 运维与排查

### 6.1 健康检查与日志

- 容器健康检查：`GET /health`（免认证），返回版本与数据库状态；端口跟随 `AB_WEBUI_PORT`
- 日志：容器标准输出 + `/app/data/log.txt`（滚动）
- 排查优先顺序：容器状态 → 健康检查 → 日志 → 连通性测试按钮

### 6.2 常见问题排查

**Q1 添加任务后一直报错 / state=error**
→ 多为保存路径问题：下载地址必须是**下载器容器内视角**的路径（对比：qB 把宿主 `/vol1/media` 挂到 `/downloads`，就要填 `/downloads/...`）。用「测试下载器连接」验证连通与认证。

**Q2 刷新后 Jellyfin 在库标签不更新**
→ 先看该集有没有「手」角标：手动覆盖优先（5.2），比对结果变化后会自动失效并提示；也可勾选后「重置标签」。没有角标仍不更新 → 检查 Jellyfin 集数编目（`IndexNumber` 是否为空，如未识别成"未知季"）、用「测试 Jellyfin 连接」验证。

**Q2b 剧集总览打开一片空白，点刷新也没用**
→ 历史缺陷（已修复）：报文拉取失败的空结果曾被写入缓存，且空缓存的过期判断形同虚设（过期计算依赖缓存内的番剧列表，空列表永不超时），导致空白总览"永久有效"。现版本：空壳缓存自动重建、拉取失败不写缓存、强制刷新失败会明确报错并保留旧缓存。老部署升级后首次读取即自愈；若仍空白，检查该订阅报文源是否可达（见 Q3）。

**Q3 TMDB / Bangumi / Mikan 一直连接失败**
→ 大陆网络需在「代理设置」配置代理；配好后用网络设置的测试按钮验证。

**Q4 想改 WebUI 端口**
→ 宿主机侧改 `ports` 映射即可；容器内端口用 `AB_WEBUI_PORT` 环境变量（每次启动生效，健康检查自动跟随）。

**Q5 qBittorrent 从其他页面（如 NAS 桌面内嵌）打开报 Unauthorized**
→ qB 的 CSRF/Referer 校验拒绝跨源内嵌；在 qB WebUI 设置关闭「启用跨站请求防护」或把嵌入页地址加入白名单（内网环境可接受）。

**Q6 透明代理（网关/TProxy 模式）开启后 NAS 外网访问失效**
→ 透明代理劫持了外网访问的回包。方案：关闭代理软件的"本机/网关劫持"模式，改为显式代理——应用内配置代理地址即可（5.3 的链路正是为此设计）。

**Q7 手动下载了种子但「已下载」标签没变**
→ 手动下载成功后自动标记；若曾手动清除标记，重新下载或手动点标签恢复。

### 6.3 数据备份与迁移

- 备份 `/app/config` 与 `/app/data` 两个目录即可完整迁移
- 换机恢复：新容器挂载旧目录启动，数据库结构自动迁移到当前版本
- 回滚版本：`docker pull shiamiea/auto-bangumi:<旧sha>` 后重建容器；**向前回滚跨数据库版本时注意**（高版本迁移过的库回到低版本可能不兼容，建议回滚前备份 data 卷）

## 7. 开发者指南

- **本地开发**：后端 `uvicorn main:app --port 7893`（backend/src），前端 `npx vite`（webui，`AB_API_TARGET` 指向后端）

- **CI/CD**：推送 main → 「Build Docker」质量流水线 + 「Build and Publish to Docker Hub」发布流水线（`docs/**`、`**.md` 不触发发布构建）
- **数据库迁移**：`backend/src/module/database/migrations.py` 追加 `Migration(n, ...)`，新表/新列需同时兼容全新安装与旧库升级（守卫式 ALTER）

## 8. FAQ

**Q：和原版 AutoBangumi 3.3 的核心差异？**
A：Jellyfin 在库比对与下载跳过、剧集总览（双视图/手动标签/手动下载/缓存）、订阅级检查计划双模式、放送星期与偏移自动检测、设置页四项连通性测试、`AB_WEBUI_PORT`、若干 UI 优化。详见 README 的「本 Fork 新增功能」。

**Q：可以和其他人共用一个 Jellyfin 吗？**
A：可以，比对只读不写；API Key 建议用只读权限的 Key。

**Q：重命名交给 MoviePilot 等外部工具时怎么配？**
A：番剧管理 → 重命名方式选 `none`，下载地址指向外部工具监控的下载目录即可；本应用仍负责订阅/抓取/投递与总览。

**Q：支持 aria2 吗？**
A：支持；密码栏填 RPC secret，用户名忽略，地址示例 `172.17.0.1:6800`。
